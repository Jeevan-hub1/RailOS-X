# RailOS HashiCorp Vault 1.16 — Deployment Guide

This directory contains Kubernetes manifests to deploy HashiCorp Vault as the
centralized secret and configuration store for the RailOS Pilot System.

## Configuration Summary

| Parameter | Value |
|-----------|-------|
| Vault version | 1.16 |
| Storage backend | File (PVC-backed `/vault/data`) |
| Replicas | 1 (single-node; scale to 3 with Raft for production HA) |
| Secrets engine | KV-v2 at `secret/` |
| Audit device | File at `/vault/audit/audit.log` (immutable, JSON per line) |
| API port | 8200 (HTTP; TLS recommended in production) |
| Namespace | `railos` |
| Data PVC | 8 Gi |
| Audit log PVC | 2 Gi |

All RailOS services read configuration from Vault instead of hardcoded ConfigMaps or Secrets,
satisfying **Requirement 37** and the configuration change logging requirement in **Task 21.4**.

## Secret Paths

| Path | Contents |
|------|----------|
| `secret/railos/thresholds` | ML model inference thresholds (confidence, probability, error) |
| `secret/railos/suppression` | Alert suppression window durations |
| `secret/railos/drift` | PSI drift detection thresholds and intervals |
| `secret/railos/deployment` | Replica counts, image tags, timeout values |
| `secret/railos/retention` | Data retention TTL values (days) |
| `secret/railos/influxdb` | InfluxDB credentials (token, org, bucket) |
| `secret/railos/minio` | MinIO credentials (access key, secret key) |
| `secret/railos/postgresql` | PostgreSQL credentials (user, password, DSN) |
| `secret/railos/kong` | Kong admin JWT secret |
| `secret/railos/mlflow` | MLflow DB password and MinIO credentials |

## Deployment

### 1. Replace placeholder secrets

Edit `02-secrets.yaml` — but note these values are only placeholders.
For the initial deployment, leave them as-is; the actual unseal key is generated by
`vault operator init` during the init Job run.

```bash
# For dev/test, you can use any placeholder — the init job will initialize Vault fresh
# For production, leave VAULT_UNSEAL_KEY as placeholder and retrieve it from init Job output
```

### 2. Apply manifests in order

```bash
kubectl apply -f infra/vault/01-configmap.yaml
kubectl apply -f infra/vault/02-secrets.yaml     # placeholder only
kubectl apply -f infra/vault/03-services.yaml
kubectl apply -f infra/vault/04-statefulset.yaml

# Wait for Vault pod to start (will be sealed/uninitialized initially)
kubectl rollout status statefulset/vault -n railos --timeout=2m

# Run initialization job
kubectl apply -f infra/vault/05-init-job.yaml

# Watch job completion
kubectl wait --for=condition=complete job/vault-init -n railos --timeout=10m
kubectl logs -n railos job/vault-init

# Apply Prometheus rules
kubectl apply -f infra/vault/06-prometheus-rules.yaml
```

### 3. Post-init actions (CRITICAL)

```bash
# 1. Get init output (contains unseal key and root token)
kubectl logs -n railos job/vault-init

# 2. Store the unseal key securely OFFLINE

# 3. Revoke the root token
kubectl exec -n railos vault-0 -- vault token revoke <ROOT_TOKEN>

# 4. Delete the bootstrap secret
kubectl delete secret vault-bootstrap -n railos

# 5. Verify secrets are populated
kubectl exec -n railos vault-0 -- vault kv get secret/railos/thresholds
kubectl exec -n railos vault-0 -- vault kv get secret/railos/deployment

# 6. Verify audit device is active
kubectl exec -n railos vault-0 -- vault audit list
kubectl exec -n railos vault-0 -- tail -5 /vault/audit/audit.log
```

### 4. Configure Kubernetes auth (for service-to-service access)

```bash
# Enable Kubernetes auth method
kubectl exec -n railos vault-0 -- \
  vault auth enable kubernetes

# Configure Kubernetes auth with the cluster API
kubectl exec -n railos vault-0 -- \
  vault write auth/kubernetes/config \
    kubernetes_host="https://kubernetes.default.svc.cluster.local:443"

# Create a policy for RailOS services to read secrets
kubectl exec -n railos vault-0 -- vault policy write railos-read - <<'EOF'
path "secret/data/railos/*" {
  capabilities = ["read", "list"]
}
path "secret/metadata/railos/*" {
  capabilities = ["read", "list"]
}
EOF

# Bind the policy to the default service account in the railos namespace
kubectl exec -n railos vault-0 -- \
  vault write auth/kubernetes/role/railos-service \
    bound_service_account_names="*" \
    bound_service_account_namespaces="railos" \
    policies="railos-read" \
    ttl="1h"
```

## Audit Log

The file audit device logs every Vault request and response in JSON format to
`/vault/audit/audit.log`. This provides an immutable record of all configuration
changes to the RailOS operational parameters (Task 21.4).

**Sample audit log entry:**
```json
{
  "time": "2026-06-10T14:23:01.456Z",
  "type": "request",
  "auth": {"client_token": "hmac-sha256:...", "accessor": "hmac-sha256:...", "policies": ["railos-read"]},
  "request": {"id": "uuid", "operation": "read", "path": "secret/data/railos/thresholds"},
  "response": {"secret": {"data": {"hmac-sha256:...": "hmac-sha256:..."}}}
}
```

**HMAC masking**: By default, values are HMAC-masked in the audit log (`log_raw=false`).
Enable `log_raw=true` only in isolated environments as it exposes secret values in the log.
